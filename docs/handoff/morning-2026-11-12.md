## What I fixed in mixodental, and the proof

**MIXO-04, the one HIGH that reaches a user.** A browser with no WebGL2 used to empty the page:
`#root` at zero children, zero canvases, no text, and two uncaught "Error creating WebGL context."
in a console no operator opens. There was no capability check, no error boundary and no
`window.onerror` anywhere in `src/`, so the same mechanism took an unsaved scene on any render-time
throw.

Now: three ways in, one surface out — no WebGL2 (checked **before** the app mounts), the engine
failing to load (which used to leave `geometryReady()` rejected with nothing rendered and nothing
said: a second blank page by a different route, found while fixing the first), and any uncaught
render error. **And the scene can be saved from it**, because a boundary cannot reach the tree that
threw and the scene lives nowhere else.

**Proved, not read:** `npm run gate:nogl` is 9/9 in a real browser. The exact measurement that read
`rootChildren 0, canvases 0, text ""` now reads `rootChildren 1, 187 chars, reason no-webgl2`.

**MIXO-03, the browser floor.** Declared as Chrome/Edge 93, Firefox 114, Safari 15.4 — and the
number worth knowing is **Firefox 114, set by module workers**, which the audit missed entirely.
Chrome had them at 80 and Safari at 15.

**The i18n guard's scope was wrong for the fifth time.** It read a list of folders; the new screen
sits in the root of `src/`, where only `App.tsx` was listed. It globs all of `src/` now.

## Three things I got wrong, written down so nobody re-derives them

- **My first draft used inline styles** with literal colour fallbacks, arguing an error screen must
  not depend on a stylesheet. `main.tsx` imports the stylesheet at module scope, so that was wrong,
  and `docs/ui-styling.md` rules 1 and 2 forbid it outright. It is classes now.
- **One of my tests compared whole renders** and so passed when two reasons shared a sentence. My
  own forgery caught it; it compares each part now. Eight forgeries in all, every one watched to
  fail first.
- **The `tail` trap bit again, through a new door.** The background-task notification said the walk
  "exited 0" because my command *ended* with `tail` — `npm run walk` actually exited 1, with the
  known `g-pre` precondition. It is not enough to keep `tail` out of a gate: keep it out of the last
  position of any command whose exit code anything will read, the harness included.
