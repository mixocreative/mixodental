# mixoDental — the whole flow, end to end

Revision 8, 2026-11-18. Folds in Fable's six corrections. Target design, not what runs today.
Items marked **[fixed today]** are already in the working tree.

## 0. Scope and users

Third-party **support generation** for dental resin printing. An STL arrives from someone else's
system; this app orients it, decides where supports may touch, builds them, lets a human fix them,
and writes an STL for a slicer. Not a scanner, not CAD, not a slicer.

| | models per session | wants |
|---|---|---|
| chairside dentist | 1–4 | "make it printable", no vocabulary lesson |
| lab technician | 10–30 (24-stage case, doubled upper/lower) | not to do the same thing 24 times |

One answer for both: **the robot does the whole case; the human is shown only what it could not
decide.**

## 1. The spine

```
DROP ──▶ CASE ◀──▶ MODEL
          ├──▶ BENCH   (Any model / saved project only)
          └──▶ PLATE   (arrange · check · write)
```

## 2. DROP — the only entry

Leads with the drop target; the purpose keys are the alternative. Today the heading leads with
"What are you making?", which is the pre-multi-file framing.

| you do | you get |
|---|---|
| drop any number of files | the case; purpose asked once |
| Aligner / Denture | the case, purpose set for the whole drop |
| Any model | the bench, no flow |
| Open a saved project | the bench, plate restored — **refused outright while any mode is live** |

**Dies:** the separate `file` chooser screen.

**Open:** one dropped file silently assumes *Aligner*. Drop a denture there and it goes into the
aligner flow unasked.

## 3. CASE — home, one card per file

A card carries a picture, a name and **one verdict**. Everything else is on the card's menu
(Remove — which offers Undo — and *Use as any model*).

Card states, all already computed:

| group | states |
|---|---|
| never became a model | `unreadable`, `too-big` (three distinct limits) |
| geometry | `clean`, `holes`, `malformed`, `repaired`, `repaired-open`, `unchanged`, `refused` |
| detection | `waiting`, `running`, `oriented`, `no-rim`, **`failed`** |

**The robot's chain is per purpose, not universal.** Today the deck runs the aligner's detection
whatever the profile was.

- **Aligner:** orient → rim → area → supports → check
- **Denture:** orient → supports → check (no rim, no area)

### Twenty-four cards on one screen

The design is reasonable for four cards and breaks at twenty-four. Rules, before any of it is built:

- **[done]** **The footer and the rail are pinned.** The case was one scrolling column with neither, so
  Arrange, Check and Export end up below twenty-four rows and the rail scrolls away from the card it
  acts on.
- **[done]** **Cards that need you sort first.** Three failures among twenty-four must not be found by
  scrolling; today rows stay in plate order.
- **[done]** **One aggregate line.** Twenty-four rows showed one "Checking…" and
  twenty-three "Waiting its turn…", and the tally is silent unless something is wrong. The batch is
  strictly sequential, with a ten-minute per-job timeout, so a case is a long unattended wait with no
  readable progress.
- **[done]** **A failed card can be retried from the card.** A failed row was never re-queued — the
  batch's `started` set only grows — so the only retry is opening it, and the row names no next
  action at all. Under auto-accept these cards ARE the human's job, which makes this the single most
  important gap in the map.
- **Tab-close: warn only, until auto-accept lands — then the case saves as it goes.** DECIDED, with
  a trigger rather than a deferral. Today there is a dirty-scene warning and no autosave, and
  detection states and finished marks are session-only, so a close or a crash loses everything
  unattended. That is tolerable while the operator is present and a run is short: the inputs are
  files they still have, so a crash mostly costs machine time. NOT ONLY machine time, though, and the
  warning must say so: a hand-drawn rim and a painted area are the operator's own work and go too. **Auto-accept is
  what creates the long unattended run**, so the case saving as it goes ships WITH step 5, not
  after it — and until then the warning must say plainly that unfinished work is not kept.

Case footer: **Arrange · Check · Export**. These exist today only on the bench, which is hidden
while the flow is open — the reason a case cannot be finished from the one screen that knows about
more than one model.

**Deleting a model:** the flow closes back here; removing the last one goes to Drop; Remove offers
Undo.

**A DONE MARK INFORMS; IT NEVER GATES, AND NEVER TRIGGERS.** Owner's ruling, 2026-11-18. The app
may say a job was done before. It must not stop the operator doing it again - the model whose print
failed, whose file was replaced, or whose supports were wrong is exactly the one they need to redo -
and completing one model is never a reason to move, or invalidate, another. **[done 2026-11-18]**:
a picked finished row opens, *Use as any model* strips it after asking, and finishing or turning a
model arranges only that model.

**AN EXPORT PATH CAN NEVER COME BACK TO THE APP.** Export is an `<a download>` on a blob URL: the
app knows the suggested name and nothing else. The browser chooses the folder, may rename the file,
and may block it silently. Project save uses `showSaveFilePicker`, but a handle gives a name, never
a disk path, and no web API links to a local file. So "show where the file went" cannot be built as
described. The most an honest version can say is **"handed to the browser as <name> at <time>"**,
session-only, as a note about what was attempted - never a link, never a claim the file is there.
A real path needs a desktop shell.

**THE APP DOES NOT TRACK WHAT IT SPAT OUT.** Owner's ruling, 2026-11-18, and it settles a question
this map previously got wrong.

The session may remember that a model was done while the browser is open. **Nothing about an export
is ever written down.** Once an STL is handed to the slicer the app has no claim on it: it cannot
know whether the file still exists, was re-sliced, was printed, or was replaced. A tick saved in a
project file claiming "exported" would be a promise the app cannot keep.

So a reopened project showing every card unfinished is **correct, not a defect** — which is what
draft 1 called it. The app knows what each model HAS (supports, a rim, a policy); it does not know
what the operator DID with it. Card verdicts therefore say what is true of the model, and the
session count stays session-only because "how many did I finish this sitting" genuinely is a fact
about the sitting.

What the file remembers is **the source** — a `.mixodental` holds the whole scene with the geometry
embedded, so it does not care whether the original STL was moved, deleted or re-exported from CAD.
A re-dropped file is a new model with no memory, which is right.

Case footer: **Arrange · Check · Export**. These exist today only on the bench, which is hidden
while the flow is open — the reason a case cannot be finished from the one screen that knows about
more than one model.

**Deleting a model:** the flow closes back here; removing the last one goes to Drop; Remove offers
Undo.

**Saved projects — SETTLED, and it changes one thing.** `encodeProject` serialises only the scene;
`dentalFinished` is session state and is reset on a non-resume start. So **reopening a saved project
shows every card unfinished** — today, and under this map.

It does not stop the case being home. The unit itself persists `supports`, `dental`, `denture` and
`placement`, so the card's verdict should be **derived from the unit**, not read from a session list.
That is the better design anyway: one source of truth, and it survives a reload. The alternative — a
finished flag on the unit — adds a field to the save format.

## 4. MODEL — tools, not steps

Same four words as the rail. Each is a mode with one bar. **Back means one level out**, and at the
first tool it means the case.

### Aligner — four tools

| tool | its states, all of which an operator can be IN |
|---|---|
| **Orient** | auto · hand-chosen tilt dial · scan busy · confirm busy (both lock Next) · free transform `off / asking / on` · the type-mismatch **Switch or Keep** prompt · Restore |
| | **Free transform gets a primary "Keep this turn".** DECIDED. It accepts the hand orientation and leaves the mode, and it is enabled whether or not a pose was proposed. *Auto orientation* keeps its own meaning — discard my turn, use the proposal — and may stay greyed when there is no proposal, which is only acceptable once it has stopped being the single way out. Today the mode's one control means "throw away what I just did" and is dead exactly when detection failed, which is the case a hand turn exists for. |
| **Rim** | drawing (the target decides: drag a point, click the line to insert, click the first to close) · a picked anchor · Close loop · Clear · Delete point · **Done refused, with the reason** |
| **Area** | Paint · Erase · Add · Select (Select itself has **Click** and **Drag over**) · tuning busy, which holds Next |
| **Supports** | Add · Select · building · **build failed** · the Back question · exporting · the check |

### Denture — two tools

**No Rim and no Area.** It also has its own worker, its own orient hook, its own supports panel
(Fix / `resolveAll`, click-to-resolve, Details, a folded Adjust, an auto-check) and its own export
pipeline. It is not the aligner flow with steps hidden; it is a second flow sharing a mode.

### At every step

The **Use as any model** confirmation modal. **[fixed today]** — it asks when there are built
supports, hand edits or a painted area, and it is now named for what it does.

**Dies:** the Next/Back wizard chain; `dental.addAnother` and its file prompt; `dental.finish`
(already invisible); `supports.dentalAuto`.

**What "Back always means the case" costs, stated rather than assumed.** Re-entry from the case
(`startItem`) only copes with a session at the first tool. From Supports it marks the unit just left
as finished with no readiness check; from Area or Rim the next card inherits the old card's stage.
So the full map **changes** that guard — it does not preserve it. The `nav-files` stage gate
**[fixed today]** is the temporary form of this, and it comes out when re-entry is made safe.

## 5. BENCH — unchanged, reached on purpose

`off ⇄ edit ⇄ zones`, transform, generate, check, five exports, Save project. Reached by *Any model*
or a saved project, and it keeps a named way back to the case **[fixed today]**.

**No-support zones stay bench-only.** The dental support area is already the inverse of a zone.

## 6. FINISH — where the job ends

Arrange so nothing overlaps, check once, write the files.

**There is no build plate, and that is an owner's ruling, not an oversight.** It was removed on
purpose: exports are per object and the slicer packs the real plate. `arrange` therefore spaces
objects apart with no plate size, the "does not fit" list is gone, and `src/config/printers.json`
is unwired. Draft 1's "one plate STL" would have reversed that decision — so it is withdrawn, and
with it the question of whether 24 arches fit a plate, which only exists if the plate comes back.

## 7. The Esc ladder

Esc goes out exactly one level, never further:

| rung | where | what it does |
|---|---|---|
| 0 | a modal, or a text field | the modal or the field takes it |
| 1 | a selection in Area or Supports | clears the selection |
| 2 | a non-Select tool in Area or Supports | back to Select |
| 3 | rim mode | leaves it, keeping the drawing |
| 4 | anything else in a step | **back one level** — **[fixed today]**, was the destructive exit |
| — | a start screen | the screen's own handler, never the workspace's — **[fixed today]** |

**Still missing, and part of this map rather than today's fix:**

- **Free transform has no rung.** Its only ways out are *Auto orientation* or a stage change, so Esc
  inside it falls through to rung 4.
- **The Back question in Supports cannot be cancelled with Esc.** It is an inline block, not a
  `<dialog>`, so rung 0 does not see it. Since today's fix Esc there runs `dental.back`, which simply
  re-raises the same question — a no-op rather than the old danger, but still not an answer.

## 8. Refusals — every one needs a screen

| where it is raised | refusals |
|---|---|
| import | `unreadable`, `too-big` (×3 limits) |
| geometry | `holes`, `malformed` |
| detection | `no-rim` (not an error), **`failed`** — "could not check the orientation" |
| orientation notices | `mismatch`, `uncertain`, `holes`, `no-area`, `angle-none-held`, `angle-check-failed` |
| tilt | scan failed |
| area | contour detection failed |
| denture | `denture-failed`, tips could not be placed |
| supports | build failed |
| export | `stale`, `failed`, `inconclusive`, `replant`, `nothing-built`, **and the partial export where some files are already written** |
| project | open refused while a mode is live; `not-project`, `damaged`, `newer`, too large to save; and a save that fails |

Under auto-accept the orientation notices become exactly the "robot could not decide" cases, so each
must light a card. **Nothing dies silently, and a refusal says the next thing to do.**

## 9. Undo

Not a side note — it crosses every boundary in this map.

- Each step sets an undo floor: "the scene the step began with".
- **Orient has no Undo at all.**
- The case draws no Undo buttons.

**The floor stops meaning anything once tools are entered out of order**, which is the whole point of
making them tools. This needs a rule before the map is built, not after.

## 10. The three decisions

1. **Home is the case.** The alternative keeps the wizard, needs two notions of "finished", and the
   24× loop stays.
2. **Clean detections auto-accept and build unattended**, review by exception. The alternative costs
   ~100 presses a case and people press through blind anyway.
3. **Export stays per object**, as the owner already ruled — the slicer packs the plate. This is
   not a decision to take; it is one already taken, recorded here so the map stops contradicting it.
