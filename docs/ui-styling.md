# Styling the UI, the CSS and the 3D colours

A guide for a designer. You can change every colour, size and font of the app without touching React or three.js code. Everything lives in three places: `src/styles/theme.css` (**the app's theme: the colours, type and geometry it actually wears**), `src/styles.css` (the set underneath, and every rule that lays a control out) and `src/ui/assets/icons/` (the icons).

## The rules

1. **No colour in code.** No `#hex`, `rgb()` or `rgba()` in any `.tsx` file or in a viewport / 3D source file. A colour is a CSS token (`--name`) in `src/styles.css`.
2. **No inline `style=` in TSX.** Style by class name in `src/styles.css`. The only exceptions are values computed from data at run time (a progress width, a brush circle size, the canvas cursor, an engine debug swatch); they are listed, each with its reason, in `src/ui/noColourLiterals.test.ts`.
3. **Every word is `t('English text')`.** The English text is the key; the Japanese and Traditional Chinese lines live in `src/locales/ja.ts` and `src/locales/zh-Hant.ts`. Never write a visible word straight into a component.
4. **Every element you may want to style has a stable name**: a class and a `data-ui="name"` attribute. Select by `[data-ui="plate-panel"]` and the name does not change when the layout does.

Tests keep these rules: `src/ui/noColourLiterals.test.ts` (rules 1 and 2), `src/i18n.test.ts` (rule 3) and `src/ui/uiStylingDoc.test.ts` (this page names every token the code uses).

## How to change a colour, a size or a font

- **A colour.** Open `src/styles/theme.css`, find the token, change its value, save. (A token the theme does not name yet is still in `:root` of `src/styles.css`; add it to the theme instead of editing the set underneath.) With `npm run dev` running, both the page and the open 3D scene recolour at once (see "How the 3D scene reads the tokens").
- **Make a state its own colour.** Many state tokens are aliases, for example `--tip-path: var(--success)`. Replace the alias with a colour and only that state changes.
- **A size.** Sizes are plain numbers in the rules of `src/styles.css` (`header { height: 56px }`, the three columns of `.workspace { grid-template-columns: 268px 1fr 300px }`, `font-size` in each rule). Corner radius and transition time are the tokens `--radius` and `--dur`.
- **A font.** The family is set once in `:root` (`font-family`) and, for Traditional Chinese, in `:root:lang(zh-Hant)`. The Zen Kaku Gothic New files are declared in `src/fonts.css` (generated by `scripts/gen-fonts-css.mjs`; do not edit it by hand).
- **An icon.** Replace its SVG file (see "Icons").
- **The batch-review viewer** (`dentalwork/batch-review/viewer.html`) has its own `tokens.css`; see "The batch-review viewer".

## The two themes

The app wears the **instrument theme** (`src/styles/theme.css`). Its shape comes from a small studio instrument: a light hardware body, white screens, dark ink, hairlines on a strict grid, tiny tracked uppercase caps on the keys, machine numerals for every number, square plates with one small round on the keys, and nothing raised or shaded. Its colour comes from the owner's reference photograph of indigo-dyed peas in a steel pot: indigo ink, a teal accent, a soft turquoise for ranges, a cream note, and the single red speck in that photograph, which is the only red in the app and means alert.

Under it is the **paper theme** (`src/styles.css` on its own), which is kept only so the two can be compared.

- The theme is one attribute, `data-theme="instrument"` on `<html>`, set at start-up by `src/ui/theme.ts`.
- `?theme=paper` in the address shows any screen in the paper set; the choice is remembered in the browser. On the catalogue page (`kit.html`) the switch is the first dropdown in the header.
- The 3D view watches that attribute, so the DOM and the scene change colour together (see "How the 3D scene reads the tokens").

### The three text styles

Every word on screen is one of three things. A designer changes a size here, not in a component.

**1. Title** - the one large line that names a full screen ("What would you like to support?"). The **serif**, sentence case, never tracked, never uppercased, one per screen. Class `.title`; the stage headings (`.start-heading`, `.dental-stage h2`) are the same style.

**2. Header** - four levels, all sans, all small tracked uppercase caps, so a header never competes with the title above it or the sentence under it: `h1` the app, `h2` a screen or panel, `h3` a group, and the field and panel label (`.panel-widget-title`, `.dental-label`, `.brand small`).

**3. Content** - sans, sentence case: `p`, `li`, `label` and the small print (`small`, `.edit-note`).

**One stack per language.** Each of the three languages names its own faces, so the Japanese face can be changed without touching English or Chinese: `--font-ui` / `--font-ui-ja` / `--font-ui-zh` for the sans, and `--font-title` / `--font-title-ja` / `--font-title-zh` for the serif. The Latin face in front is the same in all three; what changes behind it is the face that draws kana, kanji and Chinese characters. The stack follows `document.documentElement.lang`, which `src/i18n.ts` sets on every language switch, and `[lang="ja"]` / `[lang="zh-Hant"]` catch a single element marked with a language of its own.

## How the 3D scene reads the tokens

- One module reads them: `src/ui/tokenColour.ts`. `tokenColour('--name')` returns the computed value of the token as a number, `tokenCss('--name')` as `#rrggbb`. Outside a browser every colour is a neutral grey.
- `src/components/viewport/sceneColours.ts` names the token for every viewport colour (scene, model, support, marks). A component calls `useViewportColours()` and gets plain colours.
- **Live recolour.** `tokenColour.ts` keeps a revision number. It goes up when the root element's `style`, `class`, `data-theme` or `lang` attribute changes, when a `<style>` or `<link>` in `<head>` changes (a Vite hot update of `styles.css`), and when code calls `refreshTokenColours()` (a theme switch should call it). Components read it through `useTokenRevision()` (`src/ui/useTokenRevision.ts`), so they render again with the new colours; the tip markers' shared materials are recoloured on that render, and the support highlight repaints every vertex. No reload is needed.
- A rule edited by hand in the browser's devtools changes neither the attributes nor the head, so the page cannot see it. After such an edit run `mixoRefreshTokens()` in the console.
- Add a new 3D colour in three steps: a token in `:root`, one line in `sceneColours.ts` (or a `tokenColour('--name')` call), a row in the table above. The doc test fails if the row is missing.

## The two widgets every panel is built from

New panels are built from these two, so every panel in the app behaves the same way and a designer styles them once.

### Panel (`src/components/Panel.tsx`)

A titled block of controls. **Every panel has a title.** Four shapes, from two choices:

| | `collapsible` | `defaultOpen` / `open` |
| --- | --- | --- |
| A block that is always there | `false` (the default) | - |
| Opens and closes, starts open | `true` | `defaultOpen` (the default) |
| Opens and closes, starts closed | `true` | `defaultOpen={false}` |
| Opens and closes, the step remembers it | `true` | `open` + `onToggle` from the caller |

`columns={2}` or `{3}` lays the body out in that many columns of equal width. The panel is a CSS container, so a narrow panel drops its body to one column by itself - no window width, no media query.

The title is a solid bar with its words in the opposite colour, and a closed panel's bar is plainly lighter than an open one's (`--panel-title-bg` / `--panel-title-bg-closed`), so open and closed are told apart at a glance. Classes `.panel-widget`, `.panel-widget-title` (`.is-toggle` when it collapses), `.panel-widget-chevron`, `.panel-widget-body`. Names `{ui}`, `{ui}-title`, `{ui}-body`. (`.panel` is something else: the app's left and right side panels.)

### Field (`src/components/Field.tsx`)

One control with its label, and it holds whatever the control is: a text or number input, a slider, a checkbox, a segmented switch, a dropdown, or a value with nothing to change (`readOnly`, which makes it a plain row rather than a `<label>`).

- `layout="row"` (the default): label left, control right, on one line.
- `layout="stack"`: label on top. For a control that needs the width, or a label too long to sit beside one.
- A `row` field stands its label on top by itself inside a narrow panel, so the layout never has to be picked for a width.

The field carries the label, so the control inside it is bare - do not put a control that draws its own label (`NumberField`, a `.check` label) inside one, or the word appears twice. Classes `.field`, `.field--row`, `.field--stack`, `.field--read-only`, `.field-label`, `.field-control`. Names `{ui}`, `{ui}-label`, `{ui}-control`.

All four panel shapes and a two-column panel holding every kind of control are on the catalogue page (`kit.html`).

## Icons

Every icon is one SVG file in `src/ui/assets/icons/`, drawn by `src/ui/Icon.tsx` (`<Icon name="orient" />` finds `orient.svg`). To change an icon, replace its file; keep the file name, draw with `currentColor`, no fixed colour and no width or height on the root. The full list, where each appears and the rules for a replacement are in `src/ui/assets/icons/README.md`. `Icon` takes only a name and a class: size and colour come from CSS.

## The module map

`src/denture/README.md` is the map of the denture workflow (one row per module). The viewport colour modules are `src/ui/tokenColour.ts` (reads a token), `src/ui/useTokenRevision.ts` (re-render on change), `src/components/viewport/sceneColours.ts` (which token is which viewport colour) and `src/components/viewport/style.ts` (opacities and the cursor).

## The batch-review viewer

`dentalwork/batch-review/` is a separate page with its own `tokens.css`: the mixo-app-style tokens above (same names, same values), plus `--scene-*` for its 3D view (the same names as the app) and the `--layer-*` colours of the review layers. `layerColours.ts` reads this file for the GLB writers, so a layer colour is set once, here. The overhang numbers in the viewer's texts come from `summary.json` (`ruleDefaults`), never from the page.
