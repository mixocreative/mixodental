# Styling the UI, the CSS and the 3D colours

A guide for a designer. You can change every colour, size and font of the app without touching React or three.js code. Everything lives in two places: `src/styles.css` (the page and the 3D colours) and `src/ui/assets/icons/` (the icons).

## The rules

1. **No colour in code.** No `#hex`, `rgb()` or `rgba()` in any `.tsx` file or in a viewport / 3D source file. A colour is a CSS token (`--name`) in `src/styles.css`.
2. **No inline `style=` in TSX.** Style by class name in `src/styles.css`. The only exceptions are values computed from data at run time (a progress width, a brush circle size, the canvas cursor, an engine debug swatch); they are listed, each with its reason, in `src/ui/noColourLiterals.test.ts`.
3. **Every word is `t('English text')`.** The English text is the key; the Japanese and Traditional Chinese lines live in `src/locales/ja.ts` and `src/locales/zh-Hant.ts`. Never write a visible word straight into a component.
4. **Every element you may want to style has a stable name**: a class and a `data-ui="name"` attribute. Select by `[data-ui="plate-panel"]` and the name does not change when the layout does.

Tests keep these rules: `src/ui/noColourLiterals.test.ts` (rules 1 and 2), `src/i18n.test.ts` (rule 3) and `src/ui/uiStylingDoc.test.ts` (this page names every token the code uses).

## How to change a colour, a size or a font

- **A colour.** Open `src/styles.css`, find the token in `:root`, change its value, save. With `npm run dev` running, both the page and the open 3D scene recolour at once (see "How the 3D scene reads the tokens").
- **Make a state its own colour.** Many state tokens are aliases, for example `--tip-path: var(--success)`. Replace the alias with a colour and only that state changes.
- **A size.** Sizes are plain numbers in the rules of `src/styles.css` (`header { height: 56px }`, the three columns of `.workspace { grid-template-columns: 268px 1fr 300px }`, `font-size` in each rule). Corner radius and transition time are the tokens `--radius` and `--dur`.
- **A font.** The family is set once in `:root` (`font-family`) and, for Traditional Chinese, in `:root:lang(zh-Hant)`. The Zen Kaku Gothic New files are declared in `src/fonts.css` (generated by `scripts/gen-fonts-css.mjs`; do not edit it by hand).
- **An icon.** Replace its SVG file (see "Icons").
- **The batch-review viewer** (`dentalwork/batch-review/viewer.html`) has its own `tokens.css`; see "The batch-review viewer".

## How the 3D scene reads the tokens

- One module reads them: `src/ui/tokenColour.ts`. `tokenColour('--name')` returns the computed value of the token as a number, `tokenCss('--name')` as `#rrggbb`. Outside a browser every colour is a neutral grey.
- `src/components/viewport/sceneColours.ts` names the token for every viewport colour (scene, model, support, marks). A component calls `useViewportColours()` and gets plain colours.
- **Live recolour.** `tokenColour.ts` keeps a revision number. It goes up when the root element's `style`, `class`, `data-theme` or `lang` attribute changes, when a `<style>` or `<link>` in `<head>` changes (a Vite hot update of `styles.css`), and when code calls `refreshTokenColours()` (a theme switch should call it). Components read it through `useTokenRevision()` (`src/ui/useTokenRevision.ts`), so they render again with the new colours; the tip markers' shared materials are recoloured on that render, and the support highlight repaints every vertex. No reload is needed.
- A rule edited by hand in the browser's devtools changes neither the attributes nor the head, so the page cannot see it. After such an edit run `mixoRefreshTokens()` in the console.
- Add a new 3D colour in three steps: a token in `:root`, one line in `sceneColours.ts` (or a `tokenColour('--name')` call), a row in the table above. The doc test fails if the row is missing.

## Icons

Every icon is one SVG file in `src/ui/assets/icons/`, drawn by `src/ui/Icon.tsx` (`<Icon name="orient" />` finds `orient.svg`). To change an icon, replace its file; keep the file name, draw with `currentColor`, no fixed colour and no width or height on the root. The full list, where each appears and the rules for a replacement are in `src/ui/assets/icons/README.md`. `Icon` takes only a name and a class: size and colour come from CSS.

## The module map

`src/denture/README.md` is the map of the denture workflow (one row per module). The viewport colour modules are `src/ui/tokenColour.ts` (reads a token), `src/ui/useTokenRevision.ts` (re-render on change), `src/components/viewport/sceneColours.ts` (which token is which viewport colour) and `src/components/viewport/style.ts` (opacities and the cursor).

## The batch-review viewer

`dentalwork/batch-review/` is a separate page with its own `tokens.css`: the mixo-app-style tokens above (same names, same values), plus `--scene-*` for its 3D view (the same names as the app) and the `--layer-*` colours of the review layers. `layerColours.ts` reads this file for the GLB writers, so a layer colour is set once, here. The overhang numbers in the viewer's texts come from `summary.json` (`ruleDefaults`), never from the page.
